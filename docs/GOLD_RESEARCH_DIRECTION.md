# Gold 研究主张与贡献验证指南

## 当前研究主张与待验证贡献（2026-11-17）

> **让 Agent 从专家纠错中学会科学分析经验的适用条件，在条件变化时主动辨别，并减少后续项目中的错误迁移。**

本节作为后续论文、框架优化和实验设计的研究定位。Skill 抽取、复用、版本管理、人工审批及 UPDATE/FORK 是支撑机制；论文贡献需要落实到科学适用条件的学习、判别和迁移效果。以下三项均为**待验证的贡献**，不能写成已经实现、已经证明优越或首次提出。

### 1．主动发现科学经验的适用边界

当两种分析规则在源任务上都能给出正确答案时，Agent 应保留尚未区分的解释，并主动寻找能区分它们的数据、敏感性分析或关键专家问题，再将获得证据支持的判断条件写进 Gold。源任务上答对不等于适用条件已经被识别；无法区分时应记录疑问。

重点验证科学判据能否被发现，以及这些判据能否在独立队列和条件改变后的未见任务中减少错误迁移。主动提问已有先例：[Wu et al., Ask Now, Use Later: Benchmarking the Proactivity Gap in Long-Lived LLM Agents, 2026, arXiv:2605.28108v3](https://arxiv.org/abs/2605.28108v3)。其 arXiv 摘要讨论为未来任务主动获取可复用的用户偏好，页面注明获 EMNLP 2026 Main Conference 接收（2026-11-17 核对）。本项目需争取的区别是**科学判据的发现和跨队列验证**；这仍须文献比较和实验支持，不能仅以“会提问”主张新颖性。

### 2．阻止“程序跑通但科学上有错”的经验进入长期知识

分别验证：执行是否成功、主报结果是否回答本次研究问题、哪些经验有足够证据值得推广。复盘决定 KEEP、UPDATE 或 FORK 前，需要核对研究目标、实际分析对象、主结果、报告和证据是否一致。

证据不足时，Agent 应保留疑问、请求有限专家判断，并阻止未经支持的规则被晋升为可默认复用的长期经验。专家纠错、独立核验、Agent 自述与框架运行事实应分别标注来源。未来要验证学习准入证据和不确定性的处理能否减少错误经验进入 Gold 及向后续项目传播；仅增加审核提示不足以构成方法贡献。

### 3．让不同条件下都正确的经验长期共存

例如配对与独立供者分析各有适用场景。新经验出现后，Agent 应判断共同原则哪些可保留、哪些步骤需要条件化、何时值得形成独立分支，并在未见任务中选对版本或部分调用。

UPDATE/FORK 的判断应由科学适用条件与证据支持，避免新经验覆盖仍然有效的旧经验；不能用写死的数据集、关键词或“配对必分支”等规则替 Agent 决策。未来应同时检验新条件下的正确选择和旧条件下能力的保留，而非仅统计 Skill 或分支数量。

### 后续验证与解释边界

- 核心结果是后续项目中的科学错误迁移是否减少；任务完成率、程序退出成功、Skill 数量和审批通过率分别记录。
- 专家纠错后学得的条件需要在独立队列或预先隔离的未见任务中检验，区分记住单个纠错答案与学会适用条件。
- 未来对照需分开评估边界发现、学习准入和条件化共存各自的作用，并记录专家干预、反馈内容、调用成本与全部失败尝试。对照方案和量化阈值尚未冻结。
- 当前真实测试是能力案例与风险证据。U14 的数值、逐细胞明细、交付及同机离线复现通过，但正式报告仍为 HOLD；该运行不自动获得可推广经验或 Gold 演化的科学资格。
- 本次只更新研究方向文档。现有停止 checkpoint 保持封存；不据此启动新测试、UPDATE/FORK、父子路由、benchmark、冻结或发布。

## 工程责任与文档入口

科学适用条件、分析规则、验证方法、提问和分支建议由运行 Agent 基于真实证据提出。框架负责证据来源、权限、状态、版本及审批边界；Codex 负责通用框架排错和独立核验。不得将具体分析判据写死进 Native Kernel，也不得由 Codex 代写运行 Agent 的分析程序或科学报告。
